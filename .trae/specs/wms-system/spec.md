# 简易WMS系统 - 产品需求文档

## Overview

- **Summary**: 开发一款轻量级仓库管理系统（WMS），包含 Java 后端服务与响应式 Web 前端（桌面端+移动端），核心支持简易上架流程，帮助仓库人员快速完成商品上架操作。

- **Purpose**: 解决中小仓库商品入库上架流程低效、纸质记录易出错的问题，提供数字化的上架操作、真实数据库持久化与库存查询能力。

- **Target Users**: 仓库管理员（桌面端操作：数据维护、查询统计）、仓库作业人员（移动端操作：现场扫码上架）。

## Goals

- 提供响应式 Web 应用，桌面端（≥1024px）和移动端（<768px）均可正常使用

- 实现完整的简易上架流程：创建上架单→扫码/录入商品→分配库位→确认上架

- 支持基础数据管理：商品（SKU）、库位、上架单、库存

- 后端提供完整 RESTful API，数据持久化到关系型数据库，服务重启不丢失

- 界面简洁易用，操作步骤清晰；后端接口响应快速、错误信息明确

## Non-Goals

- 不实现复杂的波次、批次、序列号管理

- 不实现出库、拣货、盘点等其他仓库作业流程（本期）

- 不实现多用户登录认证、细粒度角色权限控制（本期默认单用户）

- 不对接真实硬件扫码枪，支持手动输入 SKU（摄像头扫码列为后续可选增强）

- 不实现多仓库切换、多组织架构

## Background & Context

- 当前工作目录：/workspace（空项目，仅含 README.md：spare\_parts 乐道集并库备品备件）

- 采用前后端分离架构：

  - 后端：Spring Boot 3 + JDK 17 + Spring Data JPA + 数据库（默认 H2 文件模式，零安装即可运行；可选 MySQL 8 切换配置）

  - 前端：Vue 3 + Vite + Vue Router + Pinia + Element Plus + Axios

- 面向备品备件仓库场景，SKU 数量适中，流程相对简单

## Functional Requirements

### 后端 API（基础数据）

- **FR-1 商品管理 API**: 商品（SKU/名称/规格/单位）新增、修改、删除、分页查询、按 SKU/名称模糊查询；SKU 全局唯一

- **FR-2 库位管理 API**: 库位（编码/区域/类型/备注）新增、修改、删除、分页查询、按编码/区域查询；编码全局唯一

- **FR-3 上架单管理 API**: 创建上架单（商品+计划数量，自动生成单号）、分页列表（按状态/商品筛选）、详情（含已上架明细、进度）

- **FR-4 库存查询 API**: 按商品汇总查询（SKU、商品名、总库存）；按库位明细查询（库位、商品、数量、更新时间）

### 后端 API（上架业务）

- **FR-5 上架确认 API**: 入参（上架单ID、库位ID、实际数量），事务内完成：①上架单累计已上架数量；②写入上架明细；③库存按商品+库位累加或新建；④校验：实际数量>0 且 已上架+实际 ≤ 计划数量；⑤如已上架=计划则单据状态置为"已完成"

- **FR-6 待上架单据列表 API**: 仅返回状态=pending 的上架单，含剩余待上架数量字段

### 前端页面（桌面+移动双端）

- **FR-7 商品管理页**: 搜索、新增、编辑、删除、列表

- **FR-8 库位管理页**: 搜索、新增、编辑、删除、列表

- **FR-9 上架单管理页**: 列表（状态筛选）、创建上架单、详情（进度+明细）

- **FR-10 上架作业页（移动优先）**: 选单→商品确认→库位+数量→提交确认；步骤条指引；移动端触控友好

- **FR-11 库存查询页**: 两个 Tab（按商品汇总 / 按库位明细）+ 搜索

### 通用能力

- **FR-12 响应式布局**: 桌面端侧边栏导航 + 多列栅格；移动端底部 Tab 导航 + 单列自适应；断点 768px / 1024px

- **FR-13 导航与反馈**: 5 个主路由间跳转；操作成功/失败 Toast；删除二次确认；表单提交 Loading

- **FR-14 数据初始化**: 后端首次启动自动写入演示种子数据（3 商品、6 库位、1 张待上架单、若干库存），保证开箱即用

- **FR-15 错误处理**: 后端统一异常处理 + 统一响应体 `{code, msg, data}`；前端 Axios 拦截器统一提示

## Non-Functional Requirements

- **NFR-1 易用性**: 移动端单次上架确认操作步骤 ≤ 4；移动端主操作按钮尺寸 ≥ 44×44px；文案清晰无歧义

- **NFR-2 性能**: 后端单接口 P95 响应 ≤ 300ms（数据量 ≤ 1000 条）；前端首屏加载 ≤ 3s（本地）；列表滚动流畅

- **NFR-3 兼容性**: 前端支持 Chrome 90+、Safari 14+、移动端微信内置浏览器；后端支持 JDK 17

- **NFR-4 可维护性**: 代码分层清晰（后端 controller/service/repository/entity/dto；前端 pages/components/stores/api/utils）；核心方法有基本注释

- **NFR-5 可启动性**: 提供一键启动脚本或清晰命令；后端单 jar 启动成功且 H2 数据库文件自动生成；前端 dev/build 成功

- **NFR-6 数据一致性**: 上架确认接口使用数据库事务，任何异常不出现"单据已累加但库存未增加"或反之的不一致

## Constraints

- **Technical**:

  - 后端：Spring Boot 3.x、JDK 17、Spring Data JPA、H2（默认 file 持久化）；pom.xml 中预留 MySQL 8 驱动 + 可选 profile

  - 前端：Vue 3 + Vite 4/5、Element Plus、Vue Router 4、Pinia、Axios

  - 跨域：后端配置 `/api/**` CORS 允许前端 dev 端口 5173

- **Business**: 仅覆盖上架主流程；不支持撤销上架、不处理异常上架；单仓库场景

- **Dependencies**: 构建环境需具备 JDK 17、Maven 3.8+、Node.js 18+、npm 9+

## Assumptions

- 部署环境可访问 Maven 中央仓库与 npm registry；若离线需提前准备依赖

- 单操作用户，无并发冲突；后续如需支持多人可增加乐观锁

- 商品 SKU 与库位编码全局唯一，创建后不允许修改编码本身

- H2 文件数据库满足中小规模（< 10 万条库存明细）；如需更大数据量切换 MySQL 配置即可

## Acceptance Criteria

### AC-1: 商品增删改查接口 + 前端功能可用

- **Type**: `rule`

- **Given**: 后端服务已启动，数据库已初始化

- **When**: 通过 API 或前端页面执行商品的新增、编辑、删除、查询

- **Then**: 数据库 `product` 表数据正确变化；前端列表与后端返回一致；重复 SKU 保存返回明确错误

- **Pass Condition**: ①POST `/api/products` 成功返回 data.id；②重复 SKU 返回 code≠0 且 msg 含"已存在"；③PUT 修改非 SKU 字段持久化；④DELETE 后 GET 列表不再含该记录；⑤GET `/api/products?sku=xxx` 精确/模糊匹配；⑥前端页面可完整走通上述 5 种操作并刷新不丢

- **Evidence**: curl 或 API 工具请求响应 + DB 查询结果 + 前端操作截图

### AC-2: 库位增删改查接口 + 前端功能可用

- **Type**: `rule`

- **Given**: 后端服务已启动

- **When**: 执行库位 CRUD，包括对"有库存的库位"尝试删除

- **Then**: 编码唯一校验生效；有库存库位删除时返回明确提示/禁止删除

- **Pass Condition**: ①重复编码保存失败；②删除空库位成功；③删除有库存库位返回 code≠0 且 msg 含"存在库存"或级联策略明确；④按区域筛选正确

- **Evidence**: API 请求/响应序列 + DB `location`、`inventory` 表快照

### AC-3: 上架单创建与详情接口 + 前端正确

- **Type**: `rule`

- **Given**: 已有商品数据

- **When**: 创建上架单（商品ID+计划数量>0）并查询详情

- **Then**: 生成唯一 `orderNo=PA+YYYYMMDD+序号`；状态=pending；putQty=0；详情返回商品详情、计划数量、空明细数组、进度百分比 0

- **Pass Condition**: ①创建成功返回包含 orderNo；②连续创建 3 单 orderNo 不重复；③计划数量=0 创建失败；④详情接口返回的 product 嵌套信息正确

- **Evidence**: API 请求/响应 + DB `putaway_order` 表数据 + 前端详情页截图

### AC-4: 上架确认事务性 + 移动端流程端到端

- **Type**: `rule`

- **Given**: 存在 pending 上架单（商品P、计划数量100、已上架0）；移动端视口 375×667

- **When**: 移动端进入上架作业→选单→进入库位选择→选库位L→填数量60→确认提交；再重复选库位M→填40→确认

- **Then**: 两次 API 调用后：①putQty=100，order.status=done；②putaway\_item 表生成2条记录；③inventory 表 (P,L) 有60，(P,M) 有40；④若中途抛异常（模拟超量101）则数据不发生任何变更（事务回滚）

- **Pass Condition**: DB 数据与上述一致；前端显示进度 100% + 状态"已完成"；超量/负数量提交返回错误且库存不变

- **Evidence**: 移动端操作录屏（4步流程）+ 三次 API 请求/响应 + DB 事务前后数据快照对比

### AC-5: 库存查询接口 + 前端页面数据准确

- **Type**: `rule`

- **Given**: AC-4 完成后，商品 P 在 L 有60、M 有40

- **When**: 调用库存汇总与库存明细接口 + 前端查看

- **Then**: 汇总接口返回 P 的总库存=100；明细接口返回 2 条记录；前端表格与接口一致

- **Pass Condition**: 汇总接口 Σqty = 明细接口 Σqty；前端两个 Tab 数据一致

- **Evidence**: API JSON 响应 + 前端库存页截图 + 手动验算等式

### AC-6: 响应式布局（桌面+移动）双端可用

- **Type**: `rubric`

- **Dimension**: 双端 UI 适配完整性、信息密度与触控可用性

- **Scale**: 1-5

- **Anchors**:

  - 1 = 仅桌面或仅移动可用，另一严重错位不可操作

  - 3 = 双端均可浏览，但一端存在控件重叠/文字溢出/主按钮难触达

  - 5 = 桌面侧边栏+多列栅格信息密度合理，移动单列+步骤条+大主按钮触控友好，5 个主页面在 1280×800 与 375×667 视口均无横向滚动条（表格除外）

- **Pass Threshold**: >= 4

- **Evidence**: 10 张截图（5 页面 × 2 视口）或操作录屏

### AC-7: 导航、反馈与错误提示体验

- **Type**: `rubric`

- **Dimension**: 导航流畅度、操作反馈及时性、错误信息可读性

- **Scale**: 1-5

- **Anchors**:

  - 1 = 页面跳转卡顿或失败；提交无反馈导致重复提交；错误弹窗无意义

  - 3 = 导航基本可用，但部分成功/失败提示缺失；表单错误文案模糊

  - 5 = 桌面侧边栏与移动底部 Tab 切换即时；提交按钮 loading 防抖；成功/失败 Toast 文案具体（如"上架成功 60 件"而非"操作成功"）；后端错误 msg 中文友好并在前端展示

- **Pass Threshold**: >= 4

- **Evidence**: 导航切换录屏 + 成功/失败 Toast 截图 + 3 种典型错误（重复编码、超量、空必填）提示截图

### AC-8: 代码分层与可维护性

- **Type**: `rubric`

- **Dimension**: 后端与前端代码分层、命名规范、注释完备度与重复代码控制

- **Scale**: 1-5

- **Anchors**:

  - 1 = 后端 controller 直接写 SQL；前端所有逻辑堆在 App.vue；无注释

  - 3 = 基本分层但命名不一致；跨模块 copy-paste 代码存在；少量核心方法有注释

  - 5 = 后端 entity/repository/service/dto/controller 严格分层，统一响应体 + 全局异常；前端 pages/components/stores/api/utils 分层清晰，axios 封装统一；方法命名语义化，重复代码提取为公共方法，核心 public 方法有入参出参注释

- **Pass Threshold**: >= 3

- **Evidence**: 后端目录树 + 前端目录树 + 3 段核心代码片段（上架事务、统一响应、axios 拦截器）

### AC-9: 服务可启动与构建验证

- **Type**: `rule`

- **Given**: 全新环境（空数据库/空 node\_modules）

- **When**: 按 README 步骤执行：①后端 `mvn clean package -DskipTests`；②`java -jar target/wms-backend.jar`；③前端 `npm install && npm run build`；④`npm run dev`

- **Then**: 所有命令退出码 0；后端启动日志无 ERROR；访问后端 `/api/products` 返回 200 + JSON；前端首页 200 并可成功请求 API

- **Pass Condition**: 4 步全成功，H2 数据文件 `./data/wms.mv.db` 自动生成，种子数据可查询到

- **Evidence**: 4 条命令终端输出截图或日志 + H2 控制台或 curl API 返回
